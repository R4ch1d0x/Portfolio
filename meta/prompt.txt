CODE REQUIREMENTS
- Use one shared requestAnimationFrame loop. Initialise each canvas or scene lazily with IntersectionObserver and pause it when off screen.
- Cap the pixel ratio at 2. Dispose geometries when they are replaced. Use InstancedMesh for particle pools. Use a ResizeObserver for 3D stages.
- Guard every THREE-dependent constant with a check on whether THREE loaded. If WebGL or the library fails, show a text fallback and let the rest of the course work.
- Add the global rule [hidden]{display:none!important} (it exists in style.css). Never rely on the hidden attribute with elements that set display.
- Respect prefers-reduced-motion: render a static frame for passive 3D scenes and slow or stop motion elsewhere.
- Accessibility: buttons are real <button>s with aria-pressed or role="switch", visible focus, aria-labels on canvases, 44 px touch targets in the lab.
- Responsive: no horizontal page scroll at 390 px. Tables sit in overflow-x containers. The lab grid collapses to one column under about 980 px.
- Build user-visible text with textContent, never innerHTML with dynamic data.

SAFETY AND ETHICS
- Everything is simulated in the browser. No real network requests, no scanning, no exploit code, no working attack tooling, no real targets.
- Conceptual level only: how it works, what it looks like, how to detect and stop it. Do not give step-by-step instructions to carry out an attack against a real system.
- Use fake data only: RFC 5737 and RFC 2544 IP ranges, example.test domains, invented usernames. Never use real brands or real secrets.
- Include a short "test only systems you own or are authorised to test" note in the final protection chapter and a "simulated, nothing leaves your browser" note in the footer.
